Фото и видео: конфигурация, разметка агентом и продолжение пайплайна

Визуальная ветка использует существующих агентов сбора, качества, разметки, Active Learning и обучения. Текстовый конфиг и прежние команды сохраняются. Поддерживается один класс на фотографию или короткий видеоклип. Рамки объектов, маски, трекинг и звук не входят в этот интерфейс.

**Начало работы**

Запускайте команды из корня репозитория. Установите зависимости в окружение проекта:

```sh
./.venv/bin/python -m pip install -r requirements.txt
```

Для новой минимальной установки доступны extras: `pip install -e ".[media,ui]"`; `annotation` нужен для необязательных локальных pretrained-энкодеров. Видео декодируется PyAV, поэтому отдельные системные `ffmpeg`/`ffprobe` не требуются. Первый запуск encoder с удалёнными весами требует сети; разметка skill требует доступного агента с просмотром изображений, но не отдельного API-ключа модели.

Скопируйте `configs/media.yaml`, задайте описание задачи, классы и путь к своим файлам. Пример в конфиге нужен для показа формата; измените его определения под свою задачу. `project.modality` выбирает `image` или `video`; `project.root: ..` разрешает пути от корня репозитория, когда конфиг находится в `configs/`.

Локальный источник может быть файлом, каталогом, списком `paths` или glob. Разные исходные видео получают разные группы. Для серий фотографий или нескольких файлов одной съёмки задайте общий `group_id`. Можно передать CSV/JSONL:

```yaml
collection:
  sources:
    - type: manifest
      id: my-files
      path: data/input/manifest.csv
```

Минимальные колонки manifest: `media_path`; дополнительные: `group_id`, `source_label`, `source_id`. Относительные пути внутри manifest разрешаются от его каталога. `source_label` — необязательная готовая метка источника, скрытая от агента; она не считается человеческим решением этого запуска. При разметке видео такая метка относится ко всему исходному файлу и наследуется клипами: используйте её только для файлов с однородной истинной меткой.

**Запуск и skill**

```sh
./.venv/bin/python run_pipeline.py --config configs/media.yaml --run-id my-run
```

Пайплайн соберёт файлы, проверит качество, подготовит кадры и вернёт `annotation_required`. В JSON-ответе находятся пути к `annotation_requests` и `annotation_responses`. Промежуточные данные изолированы в `data/runs/<task.id>/<run-id>/`.

Откройте проект в Codex из корня репозитория или вложенной папки и используйте `$visual-annotation`: попросите разметить подготовленный запуск, указав конфиг и `run-id`. Навык находится в `.agents/skills/visual-annotation/SKILL.md`. Если текущая рабочая папка находится выше репозитория, навык может не обнаружиться автоматически; откройте сам репозиторий либо явно передайте агенту файл SKILL.

Python не вызывает уже открытый чат. Агент читает manifest, смотрит реальные изображения, пишет JSONL и выполняет импорт через тот же CLI. В ответе нужны ID задания, версия задачи, класс или `null`, обоснование, признаки сомнения и таймкоды действительно просмотренных кадров. Полная схема и пример находятся в skill. Самооценка уверенности агента не является откалиброванной вероятностью.

```sh
./.venv/bin/python run_pipeline.py --config configs/media.yaml --run-id my-run --annotations /absolute/path/responses.jsonl
./.venv/bin/python run_pipeline.py --config configs/media.yaml --run-id my-run --status
```

Импорт допускает неполный пакет. Уже принятые ответы сохраняются; неизвестные ID, конфликтующие повторы и ответы на старую версию задания отклоняются. Если ответы записаны в стандартный `responses.jsonl`, достаточно повторить исходную команду без `--annotations`.

Для ещё не отвеченного видеоклипа можно получить более частые кадры:

```sh
./.venv/bin/python run_pipeline.py --config configs/media.yaml --run-id my-run --frames RECORD_ID --frame-step 0.25
```

После этого агент перечитывает manifest: `record_id` сохраняется, `request_id` меняется. Старые ответы к обновлённому заданию не подходят. Кадры имеют реальные временные метки декодера, нормализованные к началу видео. Разметка последовательности редких кадров не равнозначна непрерывному просмотру; короткое или неоднозначное событие требует более частых кадров либо отказа от решения.

**Ручная проверка**

Когда пакет заполнен, состояние меняется на `review_required`:

```sh
./.venv/bin/python -m streamlit run hitl_app.py
```

Выберите режим фото/видео, запуск и пример. Просмотрите материал, подтвердите класс, исправьте его и при необходимости временные границы, отклоните пример или оставьте неопределённым. Укажите имя, отметьте факт просмотра и сохраните решение. Можно сохранять по одному примеру. Неопределённые решения оставляют пакет открытым; отклонённые примеры не входят в обучение.

После проверки повторите команду запуска. Внешнюю таблицу реальных решений можно импортировать через `--reviews /absolute/path/decisions.jsonl`; обязательны `record_id`, `review_status` и `reviewer`, для исправления — `human_label`, для привязки к конкретному запросу рекомендуется `request_id`. Поддерживаемые статусы: `accepted`, `edited`, `rejected`, `uncertain`. Поля `human_start_sec`/`human_end_sec` уточняют интервал внутри подготовленного клипа. JSONL сохраняет типы точнее CSV.

Ни skill, ни обычный повтор CLI не создают человеческую проверку. `--review-mode auto-only` предназначен для технического прохода: он использует автоматические метки и завершается `completed_without_hitl`. Терминальная проверка текста остаётся доступна; для медиа нужен просмотр материала через UI или другой реальный процесс ручной разметки.

**Обучение и Active Learning**

В шаблоне обучение и AL выключены: можно разметить одно видео без требования собрать тренировочный набор. Чтобы включить обучение, задайте `training.enabled: true`; нужны итоговые метки как минимум двух классов. `training.test_size` резервирует целые группы источников до нарезки. Для одного исходного видео оставьте `test_size: 0`: модель может обучиться, но независимая оценка не появится.

Если весь отложенный набор имеет `source_label`, сохраняются метрики относительно этих предоставленных меток с указанием происхождения. Иначе модель сохраняется с `evaluation_mode: not_evaluated`. Прогнозы агента не подставляются вместо эталона. Клип и его соседние кадры не могут попасть в обучение и тест одного запуска. Уточнённый человеком интервал определяет кадры, используемые для обучения.

`features.backend`:

| Значение | Поведение |
|---|---|
| `statistics` | Локальные пространственные цветовые признаки, временные агрегаты и изменения между кадрами. Лёгкая базовая модель, без понимания семантики действий и без загрузки весов. |
| `transformers_image` | Локальный `AutoImageProcessor` + `AutoModel` с `last_hidden_state`; для нескольких кадров агрегируются признаки внешнего вида. Это не специализированный видеоэнкодер. |
| `videomae` | Локальный `VideoMAEImageProcessor` + `VideoMAEModel`; последовательность приводится к числу кадров модели. Для движения нужно подготовить достаточно реальных кадров. |

Для pretrained-варианта задайте `features.model` — локальный каталог совместимых весов или HF ID; для удалённого ID обязателен `features.revision` с зафиксированной версией. Параметры `device: auto|cpu|mps|cuda` и `local_files_only: true` управляют устройством и запретом скачивания. Автоматический режим предпочитает MPS, затем CPU. Encoder извлекает признаки для небольшого классификатора, а не размечает данные. Веса pretrained-моделей в этой реализации не скачивались и отдельный тяжёлый прогон на них не выполнялся.

`active_learning.enabled: true` включает живой цикл: начальный пакет, ручная проверка, обучение, отбор следующего пакета и новая пауза. Параметры `initial_size`, `n_iterations`, `batch_size`, `strategy` задают бюджет и стратегию (`entropy`, `margin`, `random`). Для 50 + 5×20 нужно не менее 150 тренировочных единиц сверх отложенной части. Если начальная проверенная выборка содержит только один класс, очередной пакет выбирается случайно до появления второго класса; это отмечается в истории. Отклонённые примеры расходуют бюджет запросов, но не считаются размеченными для обучения.

Сохраняются ID каждого пакета и фактическое число меток. Незапрошенная часть пула остаётся в `units.jsonl` с состоянием `pending`; AL не означает, что размечены все входные файлы. Для разметки всего набора отключите AL. Сравнительные учебные эксперименты автоматически не запускаются. Метод `ActiveLearningAgent.run_cycle` поддерживает визуальные признаки для отдельно заданных начальной выборки, пула и теста; такой режим с готовыми метками является симуляцией.

**Артефакты и повтор**

В каталоге запуска сохраняются `assets.jsonl`, `clean_assets.jsonl`, `units.jsonl`, задания/принятые ответы и ручные решения по пакетам, `labeled.jsonl` и `pipeline_state.json`. Для видео — `intervals.json` с объединёнными соседними одинаковыми метками. Для включённого обучения — `model.joblib` и описание признаков/классов в `model.metadata.json`.

Сохранённый sklearn-классификатор принимает матрицу из `agents.features.feature_matrix(extract_features(df, feature_config))`. Используйте тот же encoder и его версию, которые записаны в metadata. Для кадров с исправленными человеком границами сначала подготовьте кадры внутри этих границ; runner выполняет это автоматически.

Повтор той же команды продолжает открытый пакет. Изменение конфигурации требует нового `--run-id`; `--force` не затирает медиа-разметку. Завершённый запуск неизменяем в CLI: следующий проход получает новый ID. При ошибке исправьте причину и повторите запуск; неизвестные/устаревшие аннотации не принимаются в обход проверки.

Технические тесты используют временные изображения и небольшое сгенерированное видео. Они проверяют программный процесс и не являются учебными демонстрационными прогонами, независимой разметкой человеком или оценкой качества выбранной модели на реальных данных.
